## OCR 三引擎链

`screen.js` → `readPanel()` 对每件装备的 **副属性面板**（固定 95×120px，panel 固定显示 4 行 substat）依次调用三个引擎：

```
┌─────────────────────────────────────────────────────────────┐
│ 1. tesseract.js（主进程）                                     │
│    → 只裁图，不做额外预处理（grayscale / scale 实测无帮助）       │
│    → 硬切 4 条 strip（坐标见下）                                │
│    → 每条 strip PSM=7 + whitelist 单行模式独立识别               │
│    → 合并数字 ≥4 个即通过                                       │
│                                                              │
│ 2. winocr-zh（Windows.Media.Ocr 中文模型）                     │
│    → 直接对 scale=3 的原始 panel 识别                           │
│                                                              │
│ 3. winocr-en（Windows.Media.Ocr 英文模型）                     │
│    → 同上                                                     │
│                                                              │
│ 每个引擎返回 {value, percent, x, y}[]，解析成 [n1,n2,n3,n4]    │
│ 取 ≥4 个数字的第一组作为最终结果                                │
└─────────────────────────────────────────────────────────────┘
```

### 为什么 tesseract.js 必须逐行 strip

**根因：tesseract 的 layout analysis（textline 检测）会跳过只有单字符的 textline。**

- 两位数属性（速度 10）→ 能检测到 textline → 识别成功
- 纯数字个位数（速度 7）→ textline 被判为"太窄，疑似噪声" → 整行跳过

**实测证据**（2026-11-12，tesseract CLI v5）：

| 输入 | PSM=11 | PSM=6 | PSM=4 | PSM=7（strip） |
|------|--------|-------|-------|---------------|
| 整张 scale=4 图（35%,7,9%,8%） | 35%,9%,8% 漏7 | 35%,9%,8% 漏7 | 35%,9%,8% 漏7 | — |
| 硬切 strip=1（只含7那行） | — | — | — | **7 ✅** |

**解决方案**：绕开 layout analysis，直接把 panel 预切成 4 条 strip，每条独立用 PSM=7（treat image as single text line），不触发 textline 检测。

### strip 坐标（实测硬编码）

原始 panel 区域（`LAYOUT.valuePanelNumbers = {x:255, y:303, w:95, h:120}`）内，4 行 substat 等距排列：

| 参数 | 值 | 说明 |
|------|-----|------|
| `ROW_TOP` | 21px | 第一行字符上沿距 panel 顶部 |
| `ROW_STEP` | 26px | 每行起始 y 步进 |
| `ROW_H` | 17px | 字符高度 |
| `MARGIN` | 4px | 上下缓冲（防止切到字符边缘） |
| `scale` | 1 | 不放大（实测 scale=1/2/4 精度一致，BICUBIC 放大反可能引入伪影） |

strip 计算：
```
stripH = (ROW_H + MARGIN*2) * scale = (17+8)*1 = 25px
stripY(i) = max(0, (ROW_TOP - MARGIN + i*ROW_STEP) * scale)
```

| strip i | stripY | strip 范围 | 覆盖行 |
|---------|--------|------------|--------|
| 0 | 17 | 17-42 | 35% |
| 1 | 43 | 43-68 | 7（关键！）|
| 2 | 69 | 69-94 | 9% |
| 3 | 95 | 95-120 | 8% |

**注意**：这些是实测值，如果游戏 UI 渲染比例变了可能需要重新标定。标定方法：用 `winocr.ps1 -Path <panel图>` 拿到每行 bbox，算 `bbox.y - MARGIN` 就是 stripY。

### 预处理链

**只做一件事**：crop。实测 scale=1/2/4 识别精度完全一致，grayscale 也和彩色结果无差异，所以只裁图不做任何额外处理。contrast/invert/threshold 都不加（实测对比值：tesseract CLI 在 strip 图上加了 contrast(1) 反而可能破坏字符形状）：

```js
crop(frame, region)    // 95x120 panel，直接切
```

### tesseractOcr.js 参数

```js
const USE_WHITELIST = true;   // 启用字符集限制：只识别 0-9 % . ,
                              // （strip + PSM=7 绕开了 layout analysis，whitelist 不会再干扰单行识别）
const WHITELIST = '0123456789%.,';
const PSM_CANDIDATES = ['11', '6', '4', '3', '12'];  // 整张图多 PSM fallback

// recognise(png, opts)：
//   opts.psm 指定 → 直接用（strip 场景传 '7'）
//   不指定 → 多 PSM 轮询，取数字最多的那次
```

### applySetFilter 流程

```
openSetDialog()                    ← 打开对话框（可能被前一次遗留，先检查）
  ↓
reset All + scrollSetListToTop()   ← 1 次 swipe 回顶（幂等，确保 page 对齐）
  ↓
page 0: SUITE_COORDS fast path      ← 优先 tap 固定坐标
  ├─ 成功 → 等 dialog 关闭 → 返回
  └─ 失败 → template 匹配兜底（findSetIcon）
  ↓（page 0 没找到时）
swipe 上 1 次 → page 1
  ↓
page 1: SUITE_COORDS fast path      ← 同上
  └─ 失败 → template 匹配兜底
  ↓
tapFixedSetAndWait()               ← 关键：超时后 dismissOverlay + return true
                                      （不是 return false！因为游戏 tap icon 只勾上，
                                       dialog 不会自动关。如果 return false 再走
                                       template 匹配 = 对已勾上的再 tap 一次 = 取消勾选）
```

### tapFixedSetAndWait 设计

```
tap(x, y) → 轮询 dialogVisible() 到消失（≤2.5s）
  ├─ 消失 → grid stable → return true
  └─ 还开着（stall / 游戏 lag） → dismissOverlay() → return true
```

**绝不能 return false 再让模板匹配兜底**——游戏的套装 icon 是 toggle 状态，对已勾上的再次 tap 会取消勾选。

## 坐标速查表（1280×720）

| 元素 | 坐标/区域 | 说明 |
|------|----------|------|
| `LAYOUT.valuePanelNumbers` | `{x:255, y:303, w:95, h:120}` | 副属性面板数值列（4 行 substat） |
| `LAYOUT.filters.set` | 套装筛选按钮位置 | 点击打开对话框 |
| `SET_PANEL_REGION` | 对话框检测区域（用亮度判打开/关闭） | `luminance < 28` = 开 |
| `SET_ALL_POINT` | ~(400, 165) | 对话框「全部」按钮（reset 用） |
| 对话框关闭 | ~(150, 100) | 点左上角 dismissOverlay |

## 游戏行为（实测确认）

1. **tap 套装 icon 只勾上，dialog 不会自动关**——必须手动 dismiss
2. **对已勾上的套装 icon 再次 tap → 取消勾选**——所以 SUITE_COORDS 超时后绝不能再模板匹配
3. **套装筛选 dialog 打开时保持上一次关闭的位置**（不自动回顶）——所以每次 applySetFilter 先 reset All + 回顶
4. **跨组切换必须先 reset All 再勾新套装**——否则两个套装同时生效
5. `wantedFilters(item)` **只返回 main + sub1-4，不包含 set**——set 是 selectItem 主流程手动补的：`filters.set = setApplied ? item.set : null`

## filterCache 机制

同组装备（如 4 件 DestructionSet）的第 2-4 件会 cache hit，`applySetFilter` 不被调用，直接用缓存的 set + chip 状态。

## 定位提示一致性

`locator.js` 和 `emulatorEquip.js` 的 `rankRowsOf` 都补了 `filters.set = item.set || null`，确保「定位装备」提示和一键换装排名对得上。
