# 配装器（optimizer）自检脚本

不依赖 Electron / Jest 的纯 Node 脚本，**不会被 `yarn test`(jest) 收集**，需要手动跑。

```bash
# 仓库根目录执行，输出 ALL PASS
node test/optimizer/priority-filter-check.js
```

| 脚本 | 覆盖内容 |
|---|---|
| `priority-filter-check.js` | 「属性优先级过滤（Top %）」的截断规则：逐部位按滑块加权分数排序后保留前 N%；**边界同分装备一起保留**（最多放到名额的 2 倍）、分数为 0 的一档严格截断、关闭过滤（Top 100%）时原样返回 |

## 背景：为什么要有「同分一起保留」

优先级分数很粗。只给速度 8 分时，一堆「速度主属性 45 / 没有速度副属性」的靴子分数**完全相同**
（(0+45)/4×8 = 90）。原来的实现按位置硬切，同分里谁能留下取决于装备在数组里的原始顺序：

- 极限一速要用的那双靴子排在 42 位，名额只有 25 → 被丢掉，最高只能搜到 **310**
- 把攻击 / 命中各给 1 分，这双靴子变成 93.5 分、排到第 15 位 → 又能搜到 **315**
- 用 `docs/ZQMT_GVG2.json`（利纳柯 速度套+追击套、速度 8 分）复算：修复前池内最高 310，
  修复后 315（与「关掉过滤」的 315 一致）

所以现在截断时会把边界上同分的装备一起留下，并把扩张上限控制在一倍名额内、0 分档不扩张，
避免候选装备池无限变大而拖慢搜索。
