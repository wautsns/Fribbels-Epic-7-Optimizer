# 配装器（optimizer）自检脚本

不依赖 Electron / Jest 的纯 Node 脚本，**不会被 `yarn test`(jest) 收集**，需要手动跑。

```bash
# 仓库根目录执行，输出 ALL PASS
node test/optimizer/priority-filter-check.js
```

| 脚本 | 覆盖内容 |
|---|---|
| `priority-filter-check.js` | 「属性优先级过滤（Top %）」：组合数 ≤ 预算时不截断、超预算时按预算选百分比、按 (部位 × 套装) 分组、**选中的套装按百分比 / 未选中的套装每组只留 1 件**、边界同分在预算内补回、0 分档不补、`Top 100%` 时原样返回 |

## 现在的规则（`app/js/lib/priorityFilter.js`）

后端要把 6 个部位的候选全组合过一遍，真正的成本是**各部位候选数的乘积**，所以预筛按“组合数预算”来做：

1. 候选装备先按滑块加权分数（8 个属性优先级）打分；
2. **组合数 ≤ `COMBO_BUDGET`（2e8）→ 完全不截断**（结果可证最优，只是慢一点）；
3. 超预算 → 从宽到紧试百分比 `25 → 14 → 7 → 3 → 1`（滑块上的 Top % 只作为**上限**），取第一个落进预算的档位；
4. 一律按「部位 × 套装」分组：
   - **用户选中的套装**（4+2 / 2+2+2 时就是那几个套装；只选 4 件套 / 只选 2 件套 / 2+2 时也是选中的那些）按百分比保留，并在预算内把边界同分补回来；
   - **没选中的套装**每个 (部位, 套装) 只留 1 件 —— 搭配的另一半还空着时，任何套装都可能补进来，
     整体淘汰某个套装就会漏掉更强的套装效果；
5. 分数为 0 的那一档不补同分（否则整份装备池都会被放进来）。

运行时 `console` 会打印每个部位最终保留多少件、用了哪个百分比、估计组合数，方便排查“为什么没搜到某个解”。

## 为什么需要这套规则

原来的实现是**逐部位**（不分套装）按 Top % 截断。以 `docs/ZQMT_GVG2.json` 里的利纳柯为例
（速度套 ×4 + 追击套 ×2，只给速度 8 分）：

- 42 双“速度主属性”的靴子分数**完全相同**（(0+45)/4×8 = 90），名额只有 25 双；
- 排序只看装备在数组里的顺序，3 双**追击套**速度靴排在第 40/41/42 位 → 全被切掉；
- 池子里只剩速度套靴子，于是“2 件追击套”只能拿**盔甲**去凑：速度套盔甲 22 速 → 追击套盔甲 17 速，**−5 速**；
- 结果：最高只能搜到 **310**，而实际最优解是 **315**（把攻击/命中各给 1 分打破平局才能搜到）。

改成按 (部位 × 套装) 分组、每个套装都留代表之后，310 → **315** 稳定成立；而且每个套装的名额
按该套装自己的件数算，候选池比原来还小很多（同场景组合数 1.4e9 → 4.4e6）。

只显示“套装范围内的代表”也很划算：没有套装约束时（只选 4 件套 / 2+2 / 什么都没选），
未选中的套装每个 (部位, 套装) 只留 1 件，池子大约 20 多件/部位（组合数 ~1e8，仍在预算内），
既覆盖了「某套装 ×4/×2 的加成可能更强」的情况，又不会把搜索拖慢。
